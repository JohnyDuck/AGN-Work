## Среда

- Официальный vanilla Minecraft Java Server **1.21.4**, Java 21.
- SHA-256 проверенного серверного JAR: `1066970b09e9c671844572291c4a871cc1ac2b85838bf7004fa0e778e10f1358`.
- Minecraft DataVersion **4189**, никаких плагинов или модификаций редстоуна.
- Автоматические логические проверки: серверные `/execute if block`, `/tick freeze` и `/tick step`.
- Реальное нажатие: клиент Mineflayer с протоколом **1.21.4**, сервер работает на обычных **20 TPS**.
- Экспорт: NBT block states из сохранённых Anvil-чанков сервера, а не только из исходного генератора схемы.

### Время

Сэмплирование каждые 2 игровых тика:

- на тике **34** весь проход уже свободен;
- на тике **124** весь проход ещё свободен;
- к тику **152** пол снова полностью закрыт.

Это примерно 1,7 секунды до полного открытия, 4,5 секунды свободного прохода и 7,6 секунды полного цикла при 20 TPS. Граница каждого события измерена с точностью до 2 игровых тиков.

### Что именно импортировалось

Независимый декодер **Litemapy 0.11.0b0** прочитал основной файл, после чего полученные блоки и NBT компараторов были переданы штатному загрузчику структур vanilla 1.21.4. Механизм был повторно проверен на новом месте. Это проверяет сериализацию и работоспособность сохранённого набора блоков; это **не** утверждение о запуске графического интерфейса мода Litematica в данной среде.

### Размер и материалы

- Bounding box: **22×7×30** по X/Y/Z.
- Закрытый файл: **1019** непустых блоков, включая **12** выдвинутых поршневых головок.
- Открытый файл: **1007** непустых блоков, без отдельных головок.
- Разница — не пропавшие материалы: 12 головок создаются самими поршнями.
- Оба файла содержат NBT шести компараторов, не содержат сущностей, командных блоков или движущихся блоков `moving_piston`.

## Не проверено / ограничения

- Bedrock, другие версии Java и серверы с изменённым алгоритмом редстоуна.
- Повороты и зеркальные отражения всей схемы.
- Выгрузка чанков посреди движения.
- Вставка через каждую конкретную версию Litematica/WorldEdit.
- Ручная сборка человеком в Survival: инструкция основана на проверенном открытом сервисном состоянии, сам процесс ручной сборки не автоматизировался.

Поршни не занимают открытый проход и не выступают над полом. При осмотре технической ниши снизу/сбоку детали механизма могут быть видны; полной маскировки со всех ракурсов эта конструкция не обеспечивает.

## Воспроизводимость

В репозитории сохранены `tools/` и машинные результаты `tests/`:

- `build.py`, `controller.py` — расположение блоков;
- `integration_test.py` — циклы, повторные нажатия, сервисный режим и экспорт;
- `world_reader.py`, `export_litematic.py` — Anvil → Litematic;
- `import_test.py` — независимый декодер и повторное размещение;
- `player_click_test.js` — игровой клиент;
- `render_preview.py` — детерминированные PNG из экспортированных блоков.

**Не запускай эти тесты на важном мире:** они очищают тестовую область и меняют частоту тиков.

Зависимости Python перечислены в `tools/requirements.txt`. Для тестов нужен отдельный сервер 1.21.4 с локальным RCON, включёнными командами, `pause-when-empty-seconds=-1`. Пути/пароль задаются через `MC_TEST_SERVER` и `MC_RCON_PASSWORD`. Тестовый сервер, его JAR, мир и сторонние пакеты не включены в репозиторий или архив.

Для клиентского теста нужны npm-пакеты `mineflayer` и `vec3`; тестового пользователя `TrapdoorTester` следует выдать в операторы **после первого входа**. Для рендера нужен npm-пакет `minecraft-assets`; переменная `MC_TEXTURES` должна указывать на его `minecraft-assets/data/1.21.4/blocks`. Текстуры Minecraft принадлежат Mojang/Microsoft; в архив включены только итоговые иллюстрации, не набор текстур.
