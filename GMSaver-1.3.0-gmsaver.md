# GMSaver-1.3.0-gmsaver.jar — пересборка с изменённой командой

**Файл:** `GMSaver-1.3.0-gmsaver.jar` (замена для `GMSaver-1.3.0.jar` в папке `plugins/`)

## Что изменено

**Только одно:** из `plugin.yml` убран алиас `gms`, чтобы команда не перекрывала
`/gms` из Essentials (включение режима «выживание»).

```diff
 commands:
   gmsaver:
     description: Управление сохранением игрового режима.
-    aliases: [gms, gmkeeper]
+    aliases: [gmkeeper]
     usage: /gmsaver [check|reload|save|wipe]
```

## Что НЕ изменено

- Основная команда как была, так и осталась `/gmsaver` (она же `gmkeeper`).
  В коде плагин ищет команду строго по имени `gmsaver` (`getCommand("gmsaver")`),
  поэтому ничего больше править не пришлось.
- Ни один `.class`-файл не тронут — все 25 файлов внутри jar байт-в-байт совпадают
  с оригиналом, отличается ровно один файл: `plugin.yml`.
- Сообщения, конфиг, пермишены (`gmsaver.keep`, `gmsaver.admin`), интеграция
  с AntiRelog, логика сохранения/восстановления ГМ — всё без изменений.

## Проверка

- Список и порядок записей в архиве сохранены (26 записей), zip-целостность — OK.
- `plugin.yml` — валидный YAML, `commands: {gmsaver: aliases: [gmkeeper]}`.
- Поиск по всем файлам jar: вхождений строки-команды `gms` (не части `gmsaver`) больше нет.

## Установка

1. Удалить из `plugins/` старый `GMSaver-1.3.0.jar` (иначе вернётся алиас `/gms`).
2. Положить туда `GMSaver-1.3.0-gmsaver.jar`.
3. Перезапустить сервер (не `/reload`).

После этого `/gms` полностью свободна для Essentials (и для других плагинов, если
у них есть такая команда), а управление GMSaver — только через `/gmsaver`.
